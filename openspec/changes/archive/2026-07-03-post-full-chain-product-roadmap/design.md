## Context

The project now has a top-level full-chain evidence entry that combines:

- random real repository diagnosis
- release rehearsal
- customer-host v2
- browser self-hosted flow
- readiness history

The current state is useful but still warning. The next plan must avoid two failure modes:

- declaring the product complete when customer-host proof is still template/local evidence
- starting broad SaaS or enterprise platform features before self-hosted trial evidence is stronger

## Goals / Non-Goals

**Goals:**

- Define a short, actionable post-full-chain roadmap.
- Identify which work should happen only after real customer/external host evidence.
- Keep the plan aligned with OpenSpec, CodeGraph-assisted implementation, browser verification, and real GitHub repository evidence.

**Non-Goals:**

- No new runtime capability.
- No billing, marketplace, hosted multi-tenancy, or self-service OAuth.
- No claim that the active goal is fully complete.

## Decisions

### Decision: Roadmap is evidence-gated

The next phases are ordered by evidence value, not feature ambition. Real external host proof and warning-lane reduction come before broader organization or commercial features.

### Decision: Warning state remains explicit

The roadmap will state that full-chain warning is acceptable for rehearsal but not for final customer acceptance.

## Risks / Trade-offs

- A plan-only change can look like stalling -> mitigate by tying every phase to concrete commands and future OpenSpec candidates.
- Real external host proof may require user/customer action -> keep the goal active and list exactly what evidence is needed.
