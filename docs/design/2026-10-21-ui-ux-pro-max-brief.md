## 体验原则

1. **任务先行**：一级动作「进入演示工作区」，第二层「审阅 / 为什么 / 漂移」，真实 GitHub 数据导入放在明确标注的高级区域，不让用户一进门就面对密钥、服务商开关。
2. **操作有前提**：仓库输入先校验语法，再查是否已有工作区/是否具备访问权限；仅成功完成当前仓库检查后才可导入。已有工作区的主要动作是「打开」，不是重复导入。
3. **失败可恢复**：错误靠近字段，查询失败有独立重试入口；异步状态使用文字反馈，禁用操作有原因，禁止重复提交。
4. **易读与统一**：复用 `--bg`、`--panel`、`--ink`、`--muted`、`--accent` 等 token；扁平清晰的双列布局，减少大面积玻璃效果与无意义发光，不引入第三方动画依赖。
5. **无障碍先于美化**：可见键盘焦点、跨路由跳转主内容、完整的输入标签、状态文本，不靠颜色独自表达错误；链接与按钮触控面积 ≥44px。
6. **响应式与性能**：适配 375 / 768 / 1024 / 1440px；窄屏工作区可横向滚动标签列表，但全页不得横向溢出；遵循 `prefers-reduced-motion`，不增加外部图像和大的 JS 库。

## 首轮落地点

| 区域 | 原主要障碍 | 新交互目标 |
| --- | --- | --- |
| 首页 | 英雄区空白大、发光重、多个同级 CTA | 一眼找到演示入口，三步理解核心价值，次级快捷操作 |
| 引导演示 | 流程和快速入口相互竞争 | 单一推荐 CTA，可追随 5 步任务 |
| 工作区导航 | 大块提示占位、无 aria-current | 紧凑工作区身份、5 个稳定导航标签、当前项可识别 |
| GitHub 仓库导入 | 可能在仓库检查尚未结束或私有仓库无法访问时提交 | 输入校验、成功预检查、重复导入保护、失败重试 |
| 键盘与移动端 | 焦点 / 小屏尺寸需治理 | Skip link、清晰焦点、44px 目标、窄屏自动堆叠 |
